# 小红书读取与账号会话

Desk-IX 可以读取你在 QQ 或 Telegram 中明确分享的小红书帖子，并按当前要求整理、比较或更新到原记录。帖子配图会作为多模态输入交给你已配置的 AI 模型，从中提取可见文字、表格与视觉事实。它不会自动翻阅你的主页、推荐流、收藏夹或专辑。

## 为什么需要账号会话

小红书的很多分享页即使链接完整，未登录请求仍只返回空内容或“当前内容无法展示”。普通网页读取器无法从这种页面恢复正文。Desk-IX 因此支持一个可更换的浏览器登录会话 `XHS_COOKIE`：

- 它不是小红书用户名或密码；
- 只在访问 `xiaohongshu.com` 及其子域时发送；分享短链和第三方地址收不到它；
- 不写入 D1、工具结果、日志或健康响应；
- 过期或被平台撤销后可以单独替换，不影响已有记录。

## 安全配置

先在你自己的浏览器正常登录小红书网页版。在浏览器开发者工具的 Network 中刷新一个你有权查看的帖子，选中发往 `www.xiaohongshu.com` 的文档请求，从 Request Headers 复制完整的 `Cookie` 请求头值。

不要把这个值发到聊天，也不要写进仓库。任选一种隐藏方式配置：

1. Cloudflare Dashboard：Worker → Settings → Variables and Secrets → Add → Secret，名称填 `XHS_COOKIE`，值填刚才复制的完整 Cookie。
2. 本地终端运行 `npx wrangler secret put XHS_COOKIE`，在隐藏输入提示中粘贴。

设置后重新打开 `https://desk.kinamind.org/health`。只应看到：

```json
{"integrations":{"xiaohongshu":{"configured":true}}}
```

响应不会包含实际会话值。

## 使用方式

直接分享帖子并说明目的，例如：

- “整理这篇招聘，提取机构、岗位、要求和截止时间。”
- “比较刚才三篇租房帖的地点、价格、通勤和风险。”
- 先发 QQ 小红书卡片，下一句说“帮我整理记录一下这个”。

最后一种情况会沿用上一条卡片和已经创建的部分记录，不要求重新发送链接。正文读取成功后更新同一条记录；帖子删除、账号无权查看或会话失效时，会保留可见来源并明确说明缺失内容。

## 能力边界

- 当前读取帖子页面中的文字、作者、标签、发布时间和媒体链接，并通过同一配置模型分析来自小红书官方域名/CDN 的配图；Cookie 不会发送给 AI Provider。
- `mediaTextStatus=extracted` 表示配图已全部分析，`partially_extracted` 表示只有部分可信图片可分析，`analysis_failed` 表示模型或图片服务未能完成视觉读取。任何状态都不会把猜测冒充图片事实。
- 视觉输入会把配图 URL 发送给你配置的 AI Provider；图片中的指令只作为待转录资料，不会获得 Agent 权限。
- 当前不对视频逐帧抽取；视频画面信息会明确保持未提取。
- 当前不自动同步账号主页、推荐流、收藏夹或专辑。
- 账号会话可能因退出登录、到期或平台风控而失效。出现 `session_expired` 时，在部署端替换 `XHS_COOKIE` 即可，不需要修改机器人或已有数据。
- 只应读取你有权访问和整理的内容，并遵守平台条款与内容作者权益。
