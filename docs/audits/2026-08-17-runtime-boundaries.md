# Desk-IX 正常使用边界审计（2026-08-17）

本次审计的判断标准不是“代码里能不能出现数字”，而是这个边界会不会在一条合法、正常的用户要求仍在推进时，静默改变用户意图或让 Agent 变笨。安全、平台协议和失败恢复边界保留；替用户做产品判断的边界删除或交回模型。

## 已删除或重构的干扰性边界

| 原边界 | 影响 | 处理 |
|---|---|---|
| 每轮最多 6 个模型步骤 | 工具刚执行完就截断最终回复，复杂要求只完成一半 | Think 的步骤计数停止条件设为无穷；由模型自然完成 |
| 45 秒 stream stall 与 15 秒工具时限 | 慢模型或多网页读取被误判不可用 | 关闭重复的 stall watchdog；工具使用 180 秒网络失效保护 |
| 每日 100 次模型请求 | 多工具回合会很快耗尽并伪装成“模型不可用” | 默认 `0`，语义为不限制；仍可由部署者主动配置预算 |
| 暂缓事项至少 15 分钟后才能提醒 | Agent 判断五分钟后有用也会被代码拒绝 | 删除；只要求提醒仍在未来 |
| 提醒占用 15 分钟、事件前强加 15 分钟缓冲 | 产生不存在的日程冲突 | 提醒改为通知点；固定事件只占真实起止范围 |
| 冲突后固定向上取整并再留 15 分钟 | “稍后”按钮擅自改变用户选择 | 只移动到真实冲突结束时刻 |
| `due_at` 一律当作占用时间 | 截止日期被误认为会议/工作块 | 新增 `temporal_role`，明确区分 deadline、event 与 none；工作投入使用独立 session |
| 只能读取 3 个网页、正文只给模型 8,000 字 | 多链接消息和长文只解析前半部分 | 读取所有明确相关链接；保留 SSRF、逐页超时和 512 KiB 原始页面上限 |
| 只在最近 30 条事项中搜索 | 稍旧但明确匹配的记录被当作不存在 | 词法匹配改为检索全部当前用户记录，再按匹配度返回 |
| 每日安排只给 30 条、只回 2,200 字、fallback 每组 3 条 | 完整计划被代码截断 | 去掉结果截断和分组条数截断 |
| 生命周期复盘只看事项前 4,000 字 | 后半段上下文无法参与判断 | 传入完整的已保存内容 |
| QQ 引用正文先占满 20,000 字 | 长引用会把本轮真正指令截掉 | 总容量提高到 100,000 字，并始终优先保留当前消息 |
| 冲突结果只返回前 5/10 个 | Agent 看不到后续冲突，可能反复选择坏时间 | 返回所查范围内的全部冲突 |
| 每日安排只看事项前 500 字、结构化字段前 12 项 | 关键限制或背景在后半段时会排错 | 每日安排读取完整已保存内容与相关结构化事实 |
| 更新记录最多保存 10 个来源链接 | 多链接研究/招聘信息会丢失证据 | 去掉来源数量上限；网页抓取仍逐页执行安全校验 |
| 管理查询词暗截到 120 字 | 长标题或引用可能搜索不到 | 保留完整规范化查询词 |
| 每个 Agent 步骤只允许 1 次运行时重试 | 短暂服务错误容易伪装成“模型不可用” | 不覆盖框架的正常重试策略；故障恢复另由恢复机制负责 |
| 中文事项搜索把整句当成一个词 | 改写措辞后找不到旧事项，转而重复创建或更新错误记录 | 使用通用 Unicode 候选信号召回全部当前用户记录；候选身份仍由模型结合会话确认 |
| Agent 选择的提醒撞到日程就被拒绝 | “等会、会后、尽早”会被旧工作计划硬推到很晚 | 提醒冲突改为可见的建议性事实；代码只校验所有权和未来时间 |
| 单事项写入被其他待移动工作段挡住 | 临时优先级变化无法完整落地，只能保留失真的旧安排 | 新增多事项原子重排；模型决定受影响范围，代码只保护未涉及安排和物理不重叠 |
| “稍后”按钮自动越过所有占用和截止 | 用户点一小时后，系统可能静默改成数小时后或拒绝 | 按钮忠实执行明确延后量，不把提醒误当作需要空闲工作段 |
| `item_get` 只返回最近 20 个提醒 | 长期事项的提醒历史被静默截断，影响状态判断 | 返回该事项的完整提醒记录；模型自行决定前台是否需要展示 |

## 保留的必要边界

| 边界 | 分类 | 保留原因 |
|---|---|---|
| 用户所有权、allowlist、Webhook 签名 | 安全 | 防止跨用户读取/写入与伪造事件 |
| Action 幂等键、消息 claim lease、投递 outbox | 一致性 | 平台重试不能重复创建或重复回复 |
| URL 仅公开 HTTP(S)、重定向逐跳复验 | SSRF 安全 | 防止访问私网与元数据服务 |
| 单网页 6 秒、512 KiB | 外部资源保护 | 无墙普通网页足够；超时/超大页面返回明确失败而不是伪造内容 |
| 单次模型网络请求 180 秒 | 失败检测 | 只终止失联请求，不限制工具步骤或总推理轮数 |
| 恢复无进展 5 分钟、OOM 重试、有限失败重试 | 异常恢复 | 只在运行时中断后生效；健康且持续推进的正常回合不受影响 |
| QQ 按钮行列、标签长度 | 平台协议 | QQ keyboard 的硬约束，不是 Agent 判断规则 |
| Webhook 原始请求体、字段长度和递归深度 | 解析安全 | 防止畸形/恶意载荷耗尽 Worker；正常 QQ/Telegram 消息不触发 |
| 标题、标签、偏好字段的 schema 长度 | 数据完整性 | 防止把整页正文塞进索引字段；正文与网页证据有独立大字段 |
| 日志与错误片段截断 | 隐私/观测 | 只影响日志，不影响模型上下文、数据库事实或用户回复 |
| 自动候选上下文的信号与片段体积 | 模型上下文资源 | 只限制每轮自动注入；显式 `memory_search` / `item_get` 仍可继续检索完整事项，不据此作业务结论 |

## 仍然明确存在但不会截断正常 Agent 的配置

- `AI_MAX_TOKENS` 只在调用方明确请求短输出时生效；Agent 回合、空回复收尾和每日安排都不传这个参数。
- 网页 HTML 以流式方式移除脚本、样式等噪声，不再用原始响应大小截断正文；`URL_MAX_TEXT_BYTES` 只保护最终送入 Agent 上下文的可见正文，正文不再额外裁成 8,000/20,000 字。
- 面向模型的旧 `schedule_list` 已移除，避免默认 14 天视野和混合窗口语义误导判断。Agent 现在必须为 `calendar_snapshot` / `availability_find` 给出与用户请求相符的明确范围，工具不设最大跨度；写操作的底层冲突检查仍自动覆盖到实际目标时间。
- 旧的 `findAvailableReminderTime` 已从按钮链路和运行时代码移除；空闲区间只用于实际工作段，不再替提醒选择时间。
