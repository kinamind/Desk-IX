# Desk-IX 内部日历技能审计（2026-08-17）

## 结论

Desk-IX 现在拥有一套内部、统一、可按需加载的日历能力。它不是把更多时间关键词写进永久提示词，而是把日程能力拆成标准技能，把日历事实、区间计算和 Agent 判断分层：

- 代码负责当前用户所有权、事件区间、空档、冲突、幂等与真实写入结果。
- Agent 负责理解用户要查看、规划、改期还是复盘，以及选择何时做、是否拆分、如何取舍。
- 技能负责为某一类时间任务提供稳定流程；普通记录、网页或闲聊不加载这些细节。

## 四个按需技能

| 技能 | 触发场景 | 核心行为 |
|---|---|---|
| `calendar-read` | 今天/本周安排、空档、冲突、截止、提醒查询 | 读取明确范围的统一快照，区分四类对象，不把建议说成已保存 |
| `calendar-plan` | 安排任务、寻找时段、截止前拆分、模糊时段规划 | 结合档案与全部合格空档，由 Agent 决定时刻、段数和长度 |
| `calendar-manage` | 创建、改期、整体移动、拆分、合并、取消、批量调整 | 先解析全部对象和整体冲突，再用现有幂等写操作修改真实记录 |
| `calendar-review` | 每日/每周复盘、事件结束、逾期、重新规划 | 分开判断“是否发生”和“结果是否完成”，不按事项名称自动改状态 |

技能使用 Cloudflare Think / Agents SDK 的正式 `SkillRegistry`、`activate_skill` 和 `read_skill_resource` 链路，Markdown 以 Workers Text module 随部署打包。当前技能不运行脚本，因此不启用 Loader、shell 或脚本执行器。

## 统一日历语义

`calendar_snapshot` 在调用方指定的半开时间区间内返回：

- `event`：固定发生并占用真实持续时间；
- `deadline`：最晚完成边界，可见但不占用时间；
- `work_session`：已经保存的实际投入时段，会占用时间；
- `reminder`：通知点，可见但不占用时间。

`availability_find` 只做区间运算：合并实际忙碌区间并返回全部满足所需时长的空档，不排序、不挑选、不套工作时间模板。查询范围没有产品层最大天数；跨午夜和跨夏令时的本地日界由时区函数计算。

每日安排也读取同一份统一快照，因此不会再让交互式 Agent、提醒逻辑和 Daily Plan 各自理解一套“日程”。

## 本次删除的干扰性边界

- 移除面向模型的旧 `schedule_list`。它带默认 14 天视野并混合了忙碌、提醒等窗口，容易让长期规划遗漏，也与新的四类语义冲突。
- 永久 persona 不再塞入固定时刻、固定拆分方式或大量日程步骤；时间任务才加载相应技能。
- Daily Plan 不再要求“少量事项”“12 行以内”等固定输出规模。
- 批量改期、工作段数量、查询跨度和空档结果数量没有人为上限。
- “下午”“晚上”等模糊时段没有固定 14:00，也没有按任务类型套用时长。

继续保留的数字边界均属于安全、协议或资源完整性：Webhook/平台字段、公开 URL 与 SSRF 校验、单页读取字节数、失联请求超时、数据库字段长度和异常恢复。它们不选择日程、不限制 Agent 正常工具步骤，也不截断合法的日历查询结果。

## 诚实边界

- 当前事实源仅包含 Desk-IX 内部事项、提醒和工作时段；Google Calendar、Outlook 等外部提供方留到后续接入。
- 当前没有无限重复日程系列对象。技能遇到“每天/每周”时不会伪造已创建系列；在真正实现系列模型前，只能在用户明确要求时创建具体实例。
- 事件缺少持续时间时，历史兼容数据仍使用 60 分钟展示区间；新计划应由 Agent 根据上下文补充实际预计时长。

## 验证重点

自动化测试覆盖用户隔离、四类对象、真实冲突、deadline/reminder 非阻塞、全部空档、排除目标事项、跨午夜、一个月查询、技能注册与激活、真实模型工具循环、每日安排统一语义和夏令时日界。生产部署还需通过类型检查、lint、完整 Workers runtime 测试、Wrangler dry run、线上健康检查与 CI。
